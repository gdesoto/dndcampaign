## Compatibility boundaries

- Keep `h3` on 1.15.11. The current Nuxt 4.6.4 server uses Nitro 2 and H3 1.
  H3 2 changes the request/event APIs and belongs with a supported framework
  migration, rather than an independent dependency override. See the
  [Nuxt migration guide](https://github.com/nuxt/nuxt/blob/main/docs/1.getting-started/18.upgrade.md).
- The auth-utils boundary is resolved: the user approved 0.6 and its one-time
  logout, and reports that production already has `NUXT_APP_SECRET`. Keep that
  value stable, remove the obsolete session-password setting, and use the new
  session cookie without a dual-cookie wrapper. This does not require database
  migration or new volumes. Repository config is updated; live Unraid settings
  have not been inspected. See [deployment guidance](../DeploymentRecovery.md#authentication-secret)
  and [the upstream session migration](https://github.com/atinux/nuxt-auth-utils/pull/546).
- Use TypeScript 6.0.3 rather than 7.0.2. Current `vue-tsc` 3.3.14 requires and
  patches `typescript/lib/tsc`; TypeScript 7 removes that compiler entry point.
  Microsoft's [TypeScript 7 announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/)
  directs Vue/Volar projects to keep TypeScript 6 until tooling supports the new API.

## Cleanup and preserved coverage

- Removed the obsolete SQLite install-script approval. SQLite 13 uses N-API
  prebuilds and has no install hook. Its old `prebuild-install` dependency also
  disappeared from the lockfile; `bindings` remains required by Nitro's tracer.
- Reused the existing auth API workflow with a fixed, public dummy password hash
  generated by hash 9.1.1. Removed the unused hash imports and runtime setup from
  that test. Other API fixtures and the seed script use hash 10, while the login
  verifier still comes from auth-utils' hash 9 dependency.
- Retained legacy database adoption, date/JSON conversion, rollback, backup, and
  session tests: they protect stored data and remain necessary after these upgrades.
- Retained the export test's download-click stub. Happy DOM 21 still navigates
  download anchors rather than saving a file, so the stub prevents shared-window
  state from leaking into the next test.
- Restored isolation between Nuxt test files after shared-worker runs reproduced
  cached media-player and overlay mocks leaking into other files. Removed the
  shared-stub reset machinery from test setup; Vue component cleanup remains.
  Isolated Nuxt environments use three workers to bound cold compilation and
  memory use; unit and API projects retain their existing worker settings.
- API/browser fixtures now own a temporary artifact root alongside their test
  database. The storage audit no longer scans unrelated local artifacts and QA
  files, and teardown removes that run's files. Existing transcript/subtitle tests
  use the shared storage-root helper. A lifecycle test protects cleanup scope.
